# 1.1.0 bug hunt: findings (working notes)

## From the gallery screenshots
1. Plugin: particle outlines farther than ~32 blocks from the player are never drawn (Minecraft only shows normal
   particles within 32 blocks). A 50-block beacon box or 96-block raid area is mostly invisible. Fix: send long-distance
   ("force") particles where the API allows it, and/or draw only the part of each outline near the player.
   LogicParticles is LogicLib (read-only) -> check its API; file a Library Request if it can't force particles.

## From reading every CI log (run 44977176978, all 26 combos)
2. Paper self-test on 1.21.11, 26.1.2, 26.2, 26.3: "chunks near spawn still not loaded after 2 minutes, running anyway".
   The test still passes, but the chunk check is wrong on new Paper (spawn chunks were removed in 1.21.9, so they never
   "load" on their own). Fix the wait: load the needed chunks explicitly instead of waiting for spawn chunks.
3. Javadoc "no comment / no @param" warnings in RangeShape.java (mod/common). Cosmetic; add the docs.
4. Everything else in the logs is loader first-start noise (config files created/corrected, Realms/authlib offline,
   JDK Unsafe warnings from joml). Not ours.
5. CI resolves "latest" loader versions at build time (NeoForge 21.11.48 appeared in maven-metadata before it could be
   downloaded; Forge 26.x lookups failed). Fix: pin tested loader versions in the workflow, with a retry.
6. Java 8 (Temurin 8u514) download occasionally corrupt in setup-java -> 1.12.2 server test. Fix: retry / pin zulu 8.
